# 借鉴 Hypit 的四个思路：设计方案（待三月确认，未实施）

2026-10-21。只借思路，不复制 Hypit 任何代码（它的许可证不允许用在对外服务里）。下面所有实现都在镜感里自己写。

## 先说结论

| 点 | 建议 | 一句话理由 |
|---|---|---|
| 1. 角色槽位 | **做（第 1 阶段）** | 残留角色词的根因是"原角色的说法散落在每一镜的文字里"，让分析时就把每个角色的专属词交出来，比扩词库彻底，且不多花调用 |
| 2. 时刻标记 | **做（第 2 阶段），先粗后细** | 分析时顺手标出，不加调用；新片里的实际时间先按比例推算（免费），语音对齐留作可选付费项 |
| 3. 后期包装 | **做最小版（第 3 阶段）** | 镜感现在最缺；浏览器里用已有的 mediabunny 解码拼接 + 画布叠字幕/闪白/弹字 + 混音效，零模型调用 |
| 4. 只重算改动层 | **做（与第 3 阶段同时）** | 包装层天然零调用；出片层补一个和 countModelCalls 同口径的"干跑计数 + 费用预估" |
| 5. 一个骨架多个变体 | **推迟（第 5 阶段）** | 要改项目数据结构（一个项目多份改编），工作量大；前四步做完后自然具备基础 |

所有阶段都**不新增模型调用次数**，只有第 1、2 阶段让分析那一次的输出变长一点（估计多 5%~10% 输出 token）。语音对齐（2b）和变体（5）会花钱，单独列出，需另批。

## 点 1：角色槽位——从根上消灭"原角色词残留"

### 问题根因
镜头文字是模型用自然语言写的，原角色的物种、毛色、叫声、动作习惯直接写进了每一镜（"小猫用爪子拨手机""喵了一声"）。换角时只能事后找词替换，词表永远补不全，重写模式更是没管。

### 做法（两层，第一层就能解决大部分）
**A. 分析时让模型交出每个角色的"专属词"（不加调用）**
每个 `source_roles[i]` 新增一个槽位对象，模型在同一次分析里填好：

```ts
// 草案：加在 SourceRole 上，旧数据没有这个字段时退回现有逻辑
interface RoleSlot {
  species_terms: string[];     // 只属于这个角色物种的词：猫、小猫、喵、猫爪、猫毛……（中英都要）
  appearance_terms: string[];  // 外观专属词：三花、橘白、长毛、圆眼……
  voice: {                      // 声音单独存，编译时按新角色重写
    kind: 'speech' | 'animal' | 'none';
    description: string;        // 如"短促的喵叫"
    terms: string[];            // 喵、咕噜……
  };
  motion_terms: string[];      // 物种动作词：舔爪、伸懒腰、甩尾……
}
```

编译时，`buildRoleSwapAdapter` 的词表改成"这次分析交出来的词"，不再写死猫狗兔：
- 被换掉的角色：它的 `species_terms / appearance_terms / voice.terms` 一律替换成 `CHAR_X（新物种）` 或删掉；`motion_terms` 换成中性动作描述（"用前爪""用手"由新角色身体结构决定），或保留并标注"按新角色的身体做"。
- 没换的角色：一个词都不动（沿用现有"未换物种保持原文"的测试）。
- 旧项目（没有槽位）：退回现在的猫/狗/兔词表，行为不变。

**B. 编译后做一遍"残留检查"（确定性、零调用）**
把被换角色的专属词拿去扫最终提示词（`promptFor` 产物、`video_prompt`、首尾帧描述），命中就在出片面板标黄并列出命中的词和位置。**两种模式都检查**，"重写新故事"模式第一次有了保护。命中不自动乱改，交给用户点"一键替换"或手改。

**C.（不建议现在做）镜头文字改成占位符写法**
让模型把镜头文字写成"{CHAR_A} 拨弄手机"，物种词只放在槽位里。这是最彻底的，但会让分析结果不再是人能直接读的文字，界面上所有展示分析的地方都要跟着渲染占位符，改动面大。等 A+B 跑一段时间，残留仍多再考虑。

### 要动的文件
- `app/lib/types.ts`（`SourceRole` 加可选 `slot`）、`app/lib/schemas.ts`（`VIDEO_DNA_SCHEMA` 加字段，可选）、`app/lib/prompts.ts`（分析指令加一段"列出每个角色的专属词"）。
- `app/lib/role-swap-text.ts`：`buildRoleSwapAdapter` 的词表来源改为"槽位优先、词表兜底"；新增 `findRoleLeaks(text, roles, swapped)`。
- `app/lib/original-story.ts`：`compileOriginalStory` 的声音段改用 `voice` 槽位；产物附带残留报告。
- `app/components/VideoTargetPanel.tsx` / `PrevisShots.tsx`：显示残留提示。
- 影响范围：中等。分析结构只加可选字段，旧项目、旧缓存不受影响；分析缓存键（`gemini.ts` 的 fingerprint 含分析指令）会自然变化，新分析才带槽位。

### 费用
不加调用。分析输出预计多 200~600 token（每个角色十几个词）。

### 验收
- 单测：用三花猫项目的 DNA 加一份手写槽位，换成柯基后最终提示词里槽位词 0 命中；换成不在旧词表里的物种（比如企鹅、机器人）同样 0 命中；未换角色原文一字不变；旧 DNA（无槽位）输出与现在逐字一致。
- 重写模式：构造一份故意带"喵"的草稿，残留检查能报出来。
- 真实验证需要 **1 次重新分析**三花猫原片（gemini-3.8-flash，低思考；上次同片累计约 1.1 万 token），确认模型确实交出槽位且词表合理。需三月批准。

## 点 2：时刻标记——关键事件挂在剧情上，不写死秒数

### 数据结构草案
存在 DNA 顶层，引用镜头和动作节拍，不单独写秒数为准：

```ts
interface StoryMoment {
  id: string;                 // m1, m2…（全片唯一）
  beat_id: string;            // 属于哪一镜
  kind: 'hook' | 'reversal' | 'gag' | 'reveal' | 'danger' | 'product' | 'emotion';
  label: string;              // 人话："主人突然推门"
  anchor:
    | { type: 'dialogue'; phrase: string }       // 对白里的关键词（原文中的一小段）
    | { type: 'action'; action_index: number }   // 指向 beats[].action_beats 的第几个节拍
    | { type: 'beat'; position: number };        // 都没有时：本镜内相对位置 0~1
  source_seconds: number;     // 原片里大约第几秒（只作参考和比例换算用）
  emphasis: 1 | 2 | 3;        // 重要程度，决定包装力度（只闪一下 / 弹字 / 弹字+音效）
}
```

### 新片里怎么知道它在第几秒
- **2a（先做，免费）比例换算**：时刻在原片这一镜里的相对位置（`(source_seconds - beat.start) / 镜长`）× 新生成这一段的实际时长。动作节拍本来就带 `at_seconds`，换算准确度够做闪白、弹字。
- **2b（可选，付费，推迟）语音对齐**：有对白的段落，把生成好的视频音轨送去转写拿逐词时间，找到 `phrase` 落点。镜感现在没有任何语音转写能力，要么调中转的 Gemini 听音频（每段 1 次调用），要么在浏览器里跑本地语音模型（免费但要下载几十到几百 MB 模型，慢）。**建议先用 2a 上线，看用户是否真觉得字幕/特效对不准再做 2b。**
- 用户可在包装界面直接拖动时刻微调，存为手动修正，优先于自动结果（Hypit 也是"人工修正的对齐单独存"）。

### 要动的文件
`types.ts`、`schemas.ts`、`prompts.ts`（分析指令加"标出关键时刻"）；分析结果展示页（StudioApp 里看 DNA 的地方）加一个只读的时刻列表；`compileOriginalStory` 不受影响（时刻不进出片提示词）。影响范围：小。

### 费用
不加调用，分析输出多 100~300 token。2b 若做：每段 1 次音频调用，按段数计。

### 验收
- 单测：比例换算（生成段比原片长/短、多镜拆段、预演拆段）结果正确；`action` 锚点能跟着 `action_beats` 走。
- 真实验证与点 1 合并在同一次重新分析里（不额外花钱），人工核对标出的时刻是否就是"主人推门""猫秒睡装睡"这类点。

## 点 3：后期包装层（最小可行版）

### 流程
1. **把生成好的段落存到本地**：出片面板在任务完成后，把视频经镜感服务器转发下载进浏览器 IndexedDB（中转返回的视频地址多半不允许浏览器直接跨域读取，所以走 Worker 转发；只转发、不落服务器）。没有这一步就谈不上拼接和包装。
2. **量实际时长**：mediabunny 读出每段真实时长；按点 2a 算出每个时刻的绝对时间。
3. **自动生成包装轨**（全部可在界面上开关和改）：
   - 字幕：用每镜的台词（保留模式取翻译后的对白，重写模式取新台词），按镜头时间平均铺开；有时刻锚点的句子对齐到时刻。
   - 弹字：`emphasis ≥ 2` 的时刻弹出 `label` 的短版（可编辑），沿用镜感现有深色+翠绿风格的几套样式。
   - 闪白：`emphasis = 3` 的时刻闪一下（几帧白场渐出）。
   - 音效：时刻触发一个短音效，来自随包附带的一小组**可商用免版权**音效（需另选来源并核对许可，不能直接用本机 Mixkit 库，它的许可不允许在工具里再分发）。
   - 背景音乐：**只允许用户自己上传**，默认关；生成视频本身已带原生声音，默认不叠音乐。
4. **合成整片**：按顺序解码各段 → 裁掉"多交的秒数"（613 行那条承诺终于兑现）→ 每帧画到画布上，再叠字幕/弹字/闪白 → 原声与音效混音 → mediabunny 编码成 mp4 下载。

### 为什么用浏览器 + mediabunny
- 项目里已经在用（预演导出），不用新增依赖和服务器费用；Cloudflare Workers 跑不了 ffmpeg。
- 本机渲染助手有 ffmpeg，但它是高级选项、只有 Windows，不能当主路径；以后可做"有助手就用助手更快"的加速。
- 不用 Remotion：要服务器渲染或额外许可，体量也大，杀鸡用牛刀。
- 风险：mediabunny 解码 + 画布逐帧重编码，在弱电脑上 10 秒 720p 可能要几十秒；音频混合要自己用 Web Audio 离线渲染（OfflineAudioContext）再交给 mediabunny 的音频轨。需要先做一个技术验证（见阶段 3a）。

### 要动的文件
- 新增 `app/lib/post/`（时间换算、包装轨生成、合成导出），新增 `app/components/PostPanel.tsx`（预览 + 开关 + 微调时刻 + 导出）。
- `VideoTargetPanel.tsx`：完成后下载入库、把段落交给包装层；`relay-client.ts` 或新 API 路由：转发下载视频。
- `app/lib/previs/export.ts` 的编码部分可抽出复用。
- 影响范围：中等偏大，但几乎都是新增，现有出片流程只多一个"存到本地"的动作。

### 费用
零模型调用。下载视频走镜感服务器转发，流量费按 Cloudflare 计（很小）。

### 验收
- 单测：时间换算、裁剪秒数、字幕分配、包装轨生成。
- 真实浏览器：拿现有任意 mp4（比如三花猫原片切几段、或预演导出的视频）当"生成段"，导出整片，用 ffprobe 核对时长、音画同步、字幕出现时间；手机竖屏看一遍字幕不压脸、不出界。**开发和验收都不需要真的去生成付费视频。**
- 端到端（可选，花钱）：真出一条 seedance 片再包装，需等余额与三月批准（10 秒 480p 约 $46，720p 约 $84）。

## 点 4：只重算改动的那一层

### 分层与"指纹"
| 层 | 由什么决定（指纹的输入） | 变了要不要花钱 |
|---|---|---|
| 分析（DNA+槽位+时刻） | 原片 + 分析模型/设置 | 要（已有缓存） |
| 改编/角色 | DNA + 改编选择 + 角色设计 | 文字/生图要（已有续跑） |
| 出片提示词 | 上一层的编译结果 | 不要（本地编译） |
| 生成的段落 | 每段提示词 + 素材 + 模型参数（已有 `videoCacheKey`） | **要，最贵** |
| 时刻实际时间 | 段落文件 + 时刻定义（+ 手动修正） | 2a 不要；2b 要 |
| 包装 | 时刻时间 + 包装设置 + 音效/字幕文本 | 不要 |

- 每个段落记录"用哪份提示词指纹生成的"。改字幕、改特效、拖时刻：只重算包装层，界面明确写"本次不调用模型、不扣费"。
- 改角色或改提示词：受影响的段落标成"已过期（提示词变了）"，**旧视频保留可继续包装**，重新生成要手动点。
- 重新生成前的确认框照现有规矩写清楚：要生成哪几段、各几秒、按什么分辨率、预计费用（`video-models.ts` 的单价 × 秒数，未知价格就写"未知"，不编数），以及"已完成且提示词没变的 N 段直接复用，不重复扣费"。实现上做一个和 `countModelCalls` 同口径的 `planOutputCalls()`：只读存档、不发请求，确认框的数字就来自它，提交时再用它当硬上限（与预演的 `maxNewCalls` 同一套做法）。

### 要动的文件
`VideoTargetPanel.tsx`（段落过期标记、确认文案）、新增 `app/lib/post/` 里的指纹工具、`relay-client.ts`（复用 `runRelayTask` 去重）。影响范围：小到中。

### 验收
单测：改包装 → 计数 0；改一个角色 → 只有用到该角色的段落过期；提交数超出确认数时拒绝提交。真实浏览器看确认框文案。

## 点 5：一个骨架出多个变体（推迟）

Hypit 的变体其实是"三份独立文件 + 共享样式和流程"，不是继承覆盖。镜感对应的做法：一个项目里存多份"改编"（换角色版/换语言版/换剧情版），共享同一份 DNA、角色槽位和时刻标记，每份改编各自有角色设计、对白、出片段落和包装。
- 需要改项目保存结构（`SavedVideoProject` 从一份 brief 变成多份）、项目记录页、出片面板切换变体，工作量大。
- 每多一个变体，出片的钱就多一份（视频是主要成本）。
- 建议等第 1~4 阶段跑顺后再做；第 1 阶段的槽位和第 2 阶段的时刻本身就是变体共享的"骨架"，做完前面自然铺好了路。

## 分阶段计划

| 阶段 | 内容 | 新增调用 | 验收 |
|---|---|---|---|
| 1 | 角色槽位 + 残留检查（两种模式） | 0（分析输出略长） | 单测全过；1 次重新分析三花猫（需批准）后槽位词 0 残留 |
| 2 | 时刻标记（2a 比例换算） | 0 | 单测；与阶段 1 同一次分析里人工核对时刻 |
| 3a | 技术验证：浏览器解码多段 + 画布叠字 + 混音 + 导出 | 0 | 用现有 mp4 导出整片，ffprobe 核对 |
| 3b | 后期包装面板（段落入库、字幕/弹字/闪白/音效、导出） | 0 | 真实浏览器出整片，手机竖屏看效果 |
| 4 | 分层指纹、过期标记、`planOutputCalls` 与确认框 | 0 | 单测 + 浏览器看确认框 |
| 5 | 多变体（推迟） | 每变体一套出片费用 | 另出方案 |
